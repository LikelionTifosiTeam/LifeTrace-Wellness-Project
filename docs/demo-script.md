# AfterGlow 시연 영상 스크립트

**목표 길이 3분 00초** · 화면 녹화 + 내레이션
녹화 해상도는 **모바일 뷰(375×812)** 권장. 데스크톱으로 녹화할 경우 브라우저 창을 좁혀 모바일 레이아웃을 띄우면 서비스 성격(한 손으로 침대에서)이 그대로 드러납니다.

---

## 촬영 전 준비

1. `demo@afterglow.kr` 계정의 **오늘 체크인이 비어 있어야** 합니다. 이미 기록했다면 아래 SQL로 초기화합니다.

```sql
delete from public.clinic_responses where alert_id in (select id from public.recovery_alerts where day = 12);
delete from public.recovery_alerts where day = 12;
delete from public.daily_checkins where day = 12;
```

2. 브라우저 시크릿 창 2개를 준비합니다. (창 A = 사용자, 창 B = 클리닉)
   전환 시 로그인 대기를 줄일 수 있고, 편집에서 컷 전환이 깔끔해집니다.
3. 각 창에서 로그인 화면의 시연 계정 버튼으로 미리 한 번 로그인해 세션을 만들어 둡니다.

### 00:32 – 01:00 · 오늘 화면 (핵심)

**화면** `오늘` 탭. D+12 → 케어 카드 → `이 안내에 쓰인 신호 N개 보기` 펼치기 → `오늘 피할 것` 항목 하나 탭해서 이유 펼치기

**내레이션**
> "가장 먼저 보이는 건 D 플러스 12. 오늘이 며칠째인가입니다.
> 그 아래 케어 카드는 매일 새로 쓰입니다.
> 경과일, 어제 기록, 수면과 스트레스, 그날의 자외선과 습도를 읽고 오늘 피할 것과 하면 좋은 것을 만듭니다.
> 설계에서 가장 신경 쓴 건 **금기 목록은 어떤 경우에도 규칙 엔진이 만든다**는 겁니다.
> 금기를 언어 모델이 창작하면 의료 안전성이 깨지니까요.
> 문장 층만 언어 모델로 교체할 수 있게 분리해 두었고, 지금 화면은 규칙 엔진 문장입니다.
> 그리고 어느 쪽이 썼는지, 어떤 신호를 봤는지 사용자가 직접 펼쳐 확인할 수 있습니다."

**포인트** 항목을 펼쳐 "왜 안 되는지"가 나오는 순간을 꼭 담으세요. 정지된 리포트와 다른 지점입니다.
신호를 펼치면 맨 아래에 생성 주체가 표기됩니다 — 심사에서 "AI가 어디서 도나요?" 질문이 나올 때 이 화면이 그대로 답이 됩니다.
