## 5. 심사 기준 대응 요약

### 일상 밀착도

- 하루 30초, 사진 없이 5개 항목 탭 입력. 소요 시간을 저장해 지표로 추적
- 웨어러블·별도 앱 없이 웹만으로 완결. 기기 없는 사용자도 동일하게 개인화됨
- 알림은 회복 초기 매일 → 4주 후 주 2회로 자동 감소 (강요가 아니라 안심)
- PWA 설치 시 홈 화면에서 `/today`로 바로 진입
- 며칠 늦게 시작해도 지난 날을 소급 입력해 곡선을 이을 수 있음

### 차별적 새로움

- 시간축이 시술 **후** 90일. 기존 서비스가 비워둔 구간
- 주최사 사전 QnA가 지목한 "조회만 가능한 리포트"를 매일 갱신되는 케어 플랜으로 대체
- 케어 카드의 생성 책임을 **문장 층과 금기 목록 층으로 분리** — 금기는 항상 규칙 엔진이 만들고, 문장 층만 LLM으로 교체 가능하게 설계해 의료 안전성을 구조로 확보
  - 현재 배포본은 비용 통제를 위해 규칙 엔진 문장으로 동작하며, 카드에 생성 주체를 그대로 표기합니다. Claude API 연동은 구현·검증 완료 상태로 환경 변수 한 줄로 전환됩니다.
- 회복 기대치를 개인 컨디션으로 보정 → 피부·건강·일상이 한 곡선에서 만남
- 이탈 감지 → 동의 범위 내 클리닉 리콜이라는 **양면 구조**. 사용자와 클리닉 모두에게 가치

## 6. 개인정보 처리

시술명·시술일·방문 병원은 개인정보보호법상 건강에 관한 민감정보입니다.

- 온보딩에서 별도 동의 항목으로 분리 수집, **기본값 비동의**
- 클리닉 공유는 동의 + 이탈 감지 시에만, 알림 1건 + 전후 3일 기록으로 범위 한정
- 동의가 꺼져 있으면 DB 트리거가 `CONSENT_REQUIRED`로 공유를 거절 (프론트 버그로도 우회 불가)
- 의료진 계정은 공유된 알림과 그 전후 3일 외에는 조회 자체가 불가능 (RLS)
- 체크인 사진은 비공개 버킷 + 사용자 폴더 정책, 서명 URL로만 접근
- 설정에서 전체 기록 내보내기(JSON) 및 삭제 제공
